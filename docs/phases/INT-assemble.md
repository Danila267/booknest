## Что считать работой фазы

Фаза сделана только если её файлы есть в рабочей папке, в локальной ветке или на `origin`.
Пустая ветка, отсутствующий worktree и чат, который остановился без правок, — это «не начата». Такой фазе не создавай пустой коммит и не пиши за неё код.

На момент плейбука девять чатов первой волны были открыты в основной папке и остановились, не закоммитив страницы. Это могло измениться. Проверь заново: `git fetch origin`, `git worktree list`, `git branch -avv`, `git status` в каждой рабочей папке.

Если обычный `git commit` дописывает `Co-authored-by`, не пушь его. Пересобери незапушенный коммит так:

```bash
TREE=$(git write-tree)
PARENT=$(git rev-parse HEAD)
NEW=$(git commit-tree "$TREE" -p "$PARENT" -m "$(cat <<'EOF'
feat: short message

EOF
)")
git reset --soft "$NEW"
```

Перед пушем проверь `git log -1 --format='%B'`. В сообщении не должно быть соавтора.

Проверяй собранные ветки, а не план на бумаге. Для каждой существующей официальной ветки:

- Нет `innerHTML`, `insertAdjacentHTML`, `outerHTML`, `!important` и CSS-селекторов по id.
- `fetch` встречается только в `api/client.js` или `src/api/client.ts`.
- В CSS ровно четыре `@media`, и они лежат в файлах из `docs/contracts/css.md`.
- На каждой существующей HTML-странице один `h1`, у полей формы есть `label` и `name`.
- `node --test` запускай там, где тесты уже есть.
- `npm run lint` и `npm run build` запускай только если эти скрипты уже есть.
- Шесть книг из `docs/contracts/featured-books.json` совпадают с карточками и с началом `data/books.js`, если эти файлы есть.
- Скриншоты не подменяй. Нет файла — в аудите пункт «нет».

Падающую проверку исправляй только если это ошибка склейки. Ошибку внутри фазы опиши и не переписывай фазу целиком.
